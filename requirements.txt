# --- Verification du paiement x402 (D34-D38, app/x402.py) -------------------
# Ces trois paquets etaient deja presents, mais seulement en dependances
# transitives de `cdp-sdk`/`web3` : la porte de surete du paiement (recuperation
# de la signature EIP-712/EIP-3009) ne doit pas dependre d'un paquet qu'un
# `pip install` ulterieur peut retirer. Ils sont donc declarés ici.
#   * `eth-abi`  : encodage ABI strict du domaine et de l'autorisation ;
#   * `eth-keys` : recuperation de la cle publique (backend natif Python) ;
#   * `eth-utils`/`eth-hash` : keccak-256 et bibliotheques communes ;
#   * `pycryptodome` : backend keccak natif en production (cf. D38 et le repli
#     Python pur de `tests/keccak_fallback.py`, reserve aux postes de dev).
eth-abi==6.0.0
eth-keys==0.8.0
eth-utils==6.0.0
eth-hash==0.8.0
pycryptodome==3.24.0

# --- Comptes clients (D44, campagne commerciale) ----------------------------
# `bcrypt` est demande explicitement par la spec de l'inscription (« mot de passe
# hashe avec bcrypt »). Version epinglee comme le reste du fichier : le hachage
# du mot de passe d'un client ne doit pas dependre d'une mise a jour surprise.
# Le module n'a aucune dependance native a compiler (wheel publie cp39-abi3),
# il s'installe donc sur le VPS comme dans l'image Docker.
bcrypt==5.0.0

# `python-multipart` n'est pas optionnel des qu'une route lit un formulaire :
# Starlette leve `AssertionError: The python-multipart library must be installed
# to use form parsing` sur `await request.form()`. Les formulaires de la campagne
# commerciale (`/signup`, puis `/validate-form`) en dependent, donc le paquet est
# declare ici plutot que decouvert en production.
python-multipart==0.0.32

# --- Suivi d'audience (D67, tableau de bord d'exploitation) ------------------

# est importe a la demande (`app/audience.py`) : absent, le pays vaut « inconnu »

maxminddb==3.2.0
